IOIS FINAL V2 — DEPLOYMENT GUIDE
================================

This package fixes the duplicate registration flow and prepares the Supabase backend for:
- mandatory email verification
- permanent plan-wise Member IDs such as IOIS499SP55
- atomic numbering per plan
- referral links based on the permanent Member ID
- private member document storage in member-documents
- owner-only Storage policies
- admin-aware RLS
- mobile-friendly existing IOIS design

IMPORTANT:
1. Do NOT put service_role keys or Telegram bot tokens in frontend files.
2. Keep Authentication > Emails > Confirm sign up ON.
3. The default Supabase email sender has a low testing rate limit. A production SMTP provider is recommended.
4. Run IOIS-SUPABASE-PRODUCTION-SETUP.sql once in Supabase SQL Editor.
5. The Storage bucket member-documents is created by that SQL as PRIVATE.
6. If you already manually created member-documents and its policies, the SQL safely recreates the intended policies.
7. After running SQL, test with a NEW email address.

REGISTRATION FLOW
-----------------
Register form
 -> Supabase Auth account
 -> verification email
 -> verification link returns to register.html?complete=1
 -> pending form/files are kept in browser IndexedDB
 -> files upload to member-documents/<auth.uid()>/...
 -> database RPC creates the permanent Member ID
 -> referral URL is saved
 -> dashboard/login can be used

MEMBER ID
---------
Format:
IOIS + PLAN AMOUNT + FIRST LETTER OF FIRST NAME + FIRST LETTER OF SURNAME + PLAN SERIAL

Example:
Santosh Pandey + ₹499 + 55th ₹499 member
= IOIS499SP55

The serial is generated inside a Postgres function with row locking.
It is NOT generated by browser JavaScript.

VERY IMPORTANT
--------------
The uploaded browser files are held temporarily in IndexedDB until email verification.
If the user verifies the email on a different browser/device, the files are not available there.
In that case, return to the original device and finish registration, or re-select the files on that device.
This is intentional: payment/identity documents are not uploaded before authentication.

GITHUB PAGES
------------
Upload the contents of the ioiss-main folder to the repository root used by GitHub Pages.
The canonical registration page is register.html.
registration.html redirects to register.html.

SUPABASE URL/KEY
----------------
config.js contains only the public publishable/anon key.
Never replace it with a service_role key.

SMTP
----
If you want mandatory email verification in production, configure a verified SMTP sender/domain in Supabase Authentication > Emails > SMTP Settings.
The SQL cannot remove the provider's email sending limits.
